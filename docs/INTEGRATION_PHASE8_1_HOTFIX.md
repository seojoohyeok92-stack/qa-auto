# Phase 8.1 Hotfix 완료 보고서

검증 일시: 2026-07-30 (Asia/Seoul)

## 1. 수정 전 실제 문제

- Dashboard가 외부 API 조회와 화면 갱신을 같은 흐름으로 취급했습니다.
- 문의 원문과 기존 답변이 목록 행을 크게 늘릴 수 있었습니다.
- 승인 완료와 네이버 등록 완료가 KPI에서 혼동될 수 있었습니다.
- 선택 문의 주문 조회가 처리 단계와 연결되지 않았습니다.
- 오른쪽 상세/DPS/진행 카드의 폭과 내부 스크롤이 부족했습니다.

## 2. Dashboard 구조 변경

- 상단 작업 바, 5개 KPI, 필터, 2.1:1 목록/상세 컬럼, 전체 폭 답변 작업 영역으로 재구성했습니다.
- 목록 패널 높이를 590px로 고정하고 내부 스크롤, 고정 헤더, 52px 행, 선택 행 강조를 적용했습니다.
- 상세 패널을 문의 기본 정보, 문의 원문, 기존 답변, DPS, 7단계 처리 진행으로 분리했습니다.
- 1600px/1200px 반응형 구간과 1900px 최대 폭을 적용했습니다.

## 3. 네이버 문의 동기화 연결 방식

Dashboard와 UAT가 공통 `InquirySyncOrchestrator`를 사용합니다.

`Dashboard 버튼 → 공통 Orchestrator → 기존 load_work_queue → InquirySyncService → InquiryRepository/WorkflowRepository → Activity Log`

중복 클릭 방지, spinner, 스토어별 오류 격리, 신규/갱신/오류 집계, 완료 후 rerun을 적용했습니다. 운영 화면에는 traceback이나 인증정보를 표시하지 않고 로그 ID만 표시합니다.

## 4. 화면 새로고침과 문의 동기화 차이

- `네이버 문의 동기화`: 네이버 API에서 문의를 조회해 DB에 upsert합니다.
- `화면 새로고침`: 외부 API를 호출하지 않고 현재 DB 스냅샷만 다시 표시합니다.
- 사이드바 버튼도 `화면 새로고침`으로 변경했습니다.

## 5. 문의 목록 말줄임 처리

- 상품명 30자, 문의 요약 46자, 주문번호 18자, 스토어 16자로 제한했습니다.
- 줄바꿈과 연속 공백을 제거하고 초과 문자열에는 `…`를 붙입니다.
- 저장된 summary를 우선 사용하며, 없을 때만 원문을 안전하게 자릅니다.
- 목록 렌더링 코드에서 문의 전체 원문과 기존 답변을 제거했습니다.

## 6. 문의 상세 분리

- 전체 문의 원문은 선택 문의의 오른쪽 상세에만 표시합니다.
- 고객명은 마스킹합니다.
- 기존 네이버 답변은 값이 있을 때만 별도 expander에 표시합니다.
- 문의 원문과 기존 답변은 최대 높이 180px의 내부 스크롤을 사용합니다.

## 7. 목록 스크롤 처리

- 목록 컨테이너 높이 590px, 세로 내부 스크롤, sticky header를 적용했습니다.
- 행은 최대 52px이며 한 줄 ellipsis를 적용했습니다.
- 한 화면에서 6~8행 이상 확인할 수 있는 밀도로 구성했습니다.

## 8. KPI 명칭 수정

KPI를 `신규 문의`, `답변 초안 완료`, `검토 대기`, `승인 완료`, `오류/주의`로 구성했습니다. `승인 완료`는 approval 상태만 집계하며 post 상태와 분리합니다. 각 KPI의 목록 필터는 실제 필터 상태를 변경하고 재클릭하면 해제됩니다.

## 9. 네이버 등록 잠금 표시

- 상단에 `네이버 등록 — 잠금` 안전 배너를 표시합니다.
- 처리 진행의 7단계는 항상 `네이버 등록 — 잠금`입니다.
- 승인 완료 후에도 실제 네이버 등록 API는 호출하지 않습니다.

## 10. DPS 카드 수정

- 조회 전에는 `아직 DPS 조회를 실행하지 않았습니다.`를 표시합니다.
- 일반 `order_id`가 없으면 조회/새로고침 버튼을 비활성화하고 안내합니다.
- 상품주문번호 fallback은 허용하지 않습니다.
- 판매번호, 배송/설치 상태, 설치 예정일/유형, 최근 조회, 캐시, 조회 시간을 표시합니다.

## 11. 처리 단계 수정

`문의 수신 → 주문 확인 → DPS 확인 → Program Answer 생성 → 직원 검토 → 승인 → 네이버 등록`

주문 조회 버튼은 공통 `UatOrderService`를 사용하며 `NAVER_ORDER_LOOKUP` 단계의 완료/오류를 갱신합니다. 마지막 단계는 실제 등록 기능 상태와 무관하게 항상 잠금입니다.
